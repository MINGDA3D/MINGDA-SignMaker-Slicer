## 3. 开发语言选型

### 3.1 候选方案对比

| 语言 | 开发效率 | 性能 | GUI生态 | 几何库 | 打包分发 | 团队熟悉度 |
|------|----------|------|---------|--------|----------|------------|
| **Python** | ★★★★★ | ★★★☆☆ | ★★★★★ | ★★★★★ | ★★★★☆ | ★★★★★ |
| C++ | ★★☆☆☆ | ★★★★★ | ★★★★☆ | ★★★★★ | ★★★★★ | ★★★☆☆ |
| C# | ★★★★☆ | ★★★★☆ | ★★★★☆ | ★★★☆☆ | ★★★★★ | ★★☆☆☆ |
| Rust | ★★☆☆☆ | ★★★★★ | ★★☆☆☆ | ★★★☆☆ | ★★★★☆ | ★☆☆☆☆ |
| TypeScript | ★★★★☆ | ★★★☆☆ | ★★★★☆ | ★★☆☆☆ | ★★★☆☆ | ★★★★☆ |

### 3.2 选型决策：Python 3.11+

**选择理由**：

1. **开发效率高**
   - 动态类型语言，代码简洁
   - 丰富的标准库和第三方库
   - 快速原型开发，适合MVP迭代

2. **几何算法生态完善**
   - pyclipper：工业级多边形裁剪库（Clipper库的Python绑定）
   - Shapely：几何对象操作
   - scipy.spatial：空间算法

3. **GUI框架成熟**
   - PySide6/PyQt6：Qt官方绑定，功能完整
   - 工业级应用广泛验证

4. **DXF处理能力**
   - ezdxf：功能最完整的Python DXF库
   - 支持读写AutoCAD全版本格式

5. **团队技术储备**
   - 团队成员熟悉Python开发
   - 降低学习成本和开发风险

**性能考量**：

Python性能相对较弱，但通过以下方式缓解：

| 优化策略 | 适用场景 | 预期效果 |
|----------|----------|----------|
| NumPy向量化 | 数值计算 | 10-100x加速 |
| pyclipper C扩展 | 多边形运算 | 接近原生性能 |
| 多线程/多进程 | 批量切片 | CPU充分利用 |
| 缓存机制 | 重复计算 | 避免冗余运算 |

**版本选择：3.11+**

- 3.11相比3.10性能提升10-60%
- 更好的错误提示信息
- 类型注解增强
- 标准库更新（tomllib等）

### 3.3 被否决方案

| 方案 | 否决原因 |
|------|----------|
| **C++** | 开发周期长，团队熟悉度不足，难以快速迭代MVP |
| **C#** | 几何库生态不如Python完善，跨平台能力较弱 |
| **Rust** | 学习曲线陡峭，GUI生态不成熟 |
| **Electron+JS** | 性能开销大，几何算法库匮乏 |

## 5. 几何算法库选型

### 5.1 候选方案对比

| 库 | 多边形偏移 | 布尔运算 | 性能 | 稳定性 | 文档 |
|------|------------|----------|------|--------|------|
| **pyclipper** | ★★★★★ | ★★★★★ | ★★★★★ | ★★★★★ | ★★★☆☆ |
| Shapely | ★★★★☆ | ★★★★★ | ★★★☆☆ | ★★★★☆ | ★★★★★ |
| PyGEOS | ★★★★☆ | ★★★★★ | ★★★★☆ | ★★★★☆ | ★★★☆☆ |
| CGAL-Python | ★★★★★ | ★★★★★ | ★★★★★ | ★★★★★ | ★★☆☆☆ |

### 5.2 选型决策：pyclipper

**选择理由**：

1. **专为多边形运算设计**
   - Clipper库的Python绑定
   - 原库广泛用于CAD/CAM领域
   - 发光字切片核心需求完美匹配

2. **核心功能完整**
   ```python
   # pyclipper 核心能力
   import pyclipper

   # 多边形偏移（字壳生成核心）
   pco = pyclipper.PyclipperOffset()
   pco.AddPath(polygon, pyclipper.JT_MITER, pyclipper.ET_CLOSEDPOLYGON)
   result = pco.Execute(offset_distance * SCALE)

   # 布尔运算（孔洞处理）
   pc = pyclipper.Pyclipper()
   pc.AddPath(subject, pyclipper.PT_SUBJECT, True)
   pc.AddPath(clip, pyclipper.PT_CLIP, True)
   result = pc.Execute(pyclipper.CT_DIFFERENCE)
   ```

3. **性能优异**
   - C++核心实现
   - 整数运算避免浮点误差
   - 处理10000+顶点多边形毫秒级响应

4. **工业验证**
   - Clipper库用于多个商业CAD软件
   - 数值稳定，边界处理可靠
   - 自交多边形自动处理

**关键算法支持**：

| 算法 | 切片应用场景 | pyclipper支持 |
|------|--------------|---------------|
| 多边形偏移 | 壁厚生成、斜边收缩 | JT_MITER/ROUND/SQUARE |
| 布尔并集 | 连襟字合并 | CT_UNION |
| 布尔差集 | 孔洞处理 | CT_DIFFERENCE |
| 布尔交集 | 填充区域 | CT_INTERSECTION |
| 多边形简化 | 路径优化 | SimplifyPolygons |

### 5.3 辅助几何库

除pyclipper外，以下库作为补充：

| 库 | 用途 | 是否必需 |
|------|------|----------|
| **numpy** | 向量计算、坐标变换 | 是 |
| **scipy.spatial** | 点距离计算、凸包 | 可选 |
| **rtree** | 空间索引优化 | 可选（大量图形时） |

## 6. DXF解析库选型

### 6.1 候选方案对比

| 库 | 格式支持 | 写入能力 | 维护状态 | 文档 | 使用量 |
|------|----------|----------|----------|------|--------|
| **ezdxf** | ★★★★★ | ★★★★★ | ★★★★★ | ★★★★★ | 高 |
| dxfgrabber | ★★★☆☆ | ☆☆☆☆☆ | ★★☆☆☆ | ★★★☆☆ | 中 |
| dxflib | ★★★☆☆ | ★★★☆☆ | ★☆☆☆☆ | ★★☆☆☆ | 低 |

### 6.2 选型决策：ezdxf

**选择理由**：

1. **功能最完整的Python DXF库**
   - 支持DXF R12到R2018全版本
   - 读写双向支持
   - 支持所有标准实体类型

2. **实体类型支持**
   ```
   ezdxf 支持的关键实体:
   ├── LINE          - 直线（连襟框）
   ├── POLYLINE      - 多段线（字形轮廓）
   ├── LWPOLYLINE    - 轻量多段线（主要格式）
   ├── SPLINE        - 样条曲线（曲线字体）
   ├── CIRCLE        - 圆（底孔）
   ├── ARC           - 圆弧
   └── ELLIPSE       - 椭圆
   ```

3. **颜色识别支持**
   - 读取实体颜色属性
   - 支持ACI颜色索引
   - 支持TrueColor (RGB)
   - 满足连襟框/底孔颜色标识需求

4. **活跃维护**
   - 定期更新
   - 问题响应及时
   - 文档完善

**核心使用场景**：

```python
import ezdxf

# 读取DXF文件
doc = ezdxf.readfile("letter.dxf")
msp = doc.modelspace()

# 遍历实体
for entity in msp.query('LWPOLYLINE'):
    # 获取轮廓点
    points = list(entity.get_points())

    # 获取颜色（用于识别连襟框/底孔）
    color = entity.dxf.color
    true_color = entity.rgb  # TrueColor支持

    # 判断是否闭合
    is_closed = entity.closed
```

### 6.3 被否决方案

| 方案 | 否决原因 |
|------|----------|
| **dxfgrabber** | 只支持读取，无法导出底板/面板DXF |
| **dxflib** | 维护不活跃，文档匮乏 |
| **自研解析** | DXF格式复杂，开发成本高 |

## 7. 3D渲染技术选型

### 7.1 候选方案对比

| 技术 | 性能 | 集成难度 | 功能 | 学习成本 |
|------|------|----------|------|----------|
| **PyOpenGL** | ★★★★★ | ★★★☆☆ | ★★★★☆ | ★★★☆☆ |
| VisPy | ★★★★☆ | ★★★★☆ | ★★★★☆ | ★★★★☆ |
| ModernGL | ★★★★★ | ★★★☆☆ | ★★★★☆ | ★★★☆☆ |
| VTK | ★★★★★ | ★★☆☆☆ | ★★★★★ | ★★☆☆☆ |
| PyVista | ★★★★☆ | ★★★★☆ | ★★★★★ | ★★★★☆ |

### 7.2 选型决策：PyOpenGL + numpy

**选择理由**：

1. **Qt集成最佳**
   - QOpenGLWidget原生支持
   - 共享OpenGL上下文
   - 事件处理无缝对接

2. **性能满足需求**
   - 直接调用OpenGL API
   - numpy配合实现高效批量渲染
   - VBO/VAO支持

3. **控制粒度细**
   - 完全控制渲染管线
   - 便于实现特定效果（分层显示、颜色编码等）
   - 自定义着色器支持

**渲染需求分析**：

| 需求 | 实现方案 |
|------|----------|
| 路径线条渲染 | GL_LINE_STRIP |
| 分层显示 | Z轴偏移 + 颜色区分 |
| 挤出机颜色 | 统一颜色映射 |
| 视角控制 | 旋转矩阵变换 |
| 逐层动画 | 层遮罩渲染 |

**3D预览架构**：

```
Preview3D 渲染架构
│
├── QOpenGLWidget (PySide6)
│   ├── initializeGL()    - 初始化OpenGL上下文
│   ├── paintGL()         - 渲染循环
│   └── resizeGL()        - 视口调整
│
├── 渲染数据
│   ├── layers: List[Layer]  - 切片层数据
│   ├── VBO缓冲             - 顶点数据
│   └── 颜色映射             - 挤出机颜色
│
└── 交互控制
    ├── 鼠标旋转           - arcball控制
    ├── 滚轮缩放           - 透视调整
    └── 层滑块             - 逐层显示
```

### 7.3 性能优化策略

| 策略 | 说明 |
|------|------|
| VBO批量渲染 | 减少API调用次数 |
| 层级LOD | 远距离简化显示 |
| 视锥剔除 | 只渲染可见部分 |
| 增量更新 | 参数变化时局部刷新 |

### 7.4 备选方案评估

**VisPy** 作为备选方案保留：
- 如果PyOpenGL开发复杂度过高
- 如果需要更高级的可视化功能
- VisPy提供更高层封装，集成仍然良好

### 9.2 选型决策：PyInstaller

**选择理由**：

1. **成熟稳定**
   - 10年+历史
   - 广泛使用验证
   - 问题解决方案丰富

2. **PySide6支持良好**
   - 自动检测Qt依赖
   - 插件自动打包
   - hook机制完善

3. **单文件/单目录**
   - 支持单exe发布
   - 便于分发

4. **跨平台**
   - Windows/macOS/Linux
   - 相同配置跨平台

**打包配置**：

```python
# signmaker.spec

    ...
)
```

- 单文件模式：~100MB（含压缩）
